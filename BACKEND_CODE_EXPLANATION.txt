                        1. SERVER SETUP & CONFIGURATION
================================================================================

File: backend/server.js

// Import required modules
const express = require('express');
const cors = require('cors');
const app = express();
const PORT = process.env.PORT || 5000;

EXPLANATION:
- express: Web framework for Node.js that simplifies building web applications
- cors: Cross-Origin Resource Sharing middleware to allow frontend requests
- app: Express application instance
- PORT: Server port (5000 for development, or environment variable for production)

================================================================================
                             2. MIDDLEWARE EXPLANATION
================================================================================

// Middleware setup
app.use(cors()); // Enable CORS for frontend requests
app.use(express.json()); // Parse JSON bodies

EXPLANATION:

CORS MIDDLEWARE:
- Purpose: Allows your React frontend (running on localhost:5173) to make requests
  to your backend (running on localhost:5000)
- Without CORS, browsers block cross-origin requests for security
- Configuration: Allows all origins in development (not recommended for production)

JSON PARSER MIDDLEWARE:
- Purpose: Automatically parses incoming JSON request bodies
- Converts JSON strings to JavaScript objects
- Makes req.body available in your route handlers

================================================================================
                                4. API ENDPOINTS
================================================================================

4.1 FOOD ITEMS ENDPOINTS:

GET /api/foods
- Purpose: Retrieve all food items
- Response: Array of all food objects
- No parameters required

GET /api/foods/:id
- Purpose: Retrieve a specific food item by ID
- Parameters: id (in URL path)
- Response: Single food object or 404 error

CODE EXPLANATION:
app.get('/api/foods', (req, res) => {
  try {
    res.json(foods); // Send all foods as JSON response
  } catch (error) {
    res.status(500).json({ error: 'Failed to fetch food items' });
  }
});

app.get('/api/foods/:id', (req, res) => {
  try {
    const food = foods.find(f => f.id === parseInt(req.params.id));
    if (!food) {
      return res.status(404).json({ error: 'Food item not found' });
    }
    res.json(food);
  } catch (error) {
    res.status(500).json({ error: 'Failed to fetch food item' });
  }
});

4.2 ORDER ENDPOINTS:

POST /api/orders
- Purpose: Create a new order
- Request Body: { items, totalAmount, userId, deliveryAddress }
- Response: Created order object

GET /api/orders/user/:userId
- Purpose: Get all orders for a specific user
- Parameters: userId (in URL path)
- Response: Array of user's orders

PUT /api/orders/:id
- Purpose: Update order status
- Parameters: id (in URL path)
- Request Body: { status }
- Response: Updated order object

DELETE /api/orders/:id
- Purpose: Delete an order
- Parameters: id (in URL path)
- Response: Success message

CODE EXPLANATION:
app.post('/api/orders', (req, res) => {
  try {
    const { items, totalAmount, userId, deliveryAddress } = req.body;
    
    const newOrder = {
      id: orders.length + 1,
      items,
      totalAmount,
      userId,
      deliveryAddress,
      status: 'pending',
      createdAt: new Date().toISOString()
    };
    
    orders.push(newOrder);
    res.status(201).json(newOrder); // 201 = Created
  } catch (error) {
    res.status(500).json({ error: 'Failed to create order' });
  }
});

4.3 AUTHENTICATION ENDPOINTS:

POST /api/auth/login
- Purpose: User login
- Request Body: { email, password }
- Response: { success, user, token }

POST /api/auth/register
- Purpose: User registration
- Request Body: { name, email, password }
- Response: { success, user, token }

CODE EXPLANATION:
app.post('/api/auth/login', (req, res) => {
  try {
    const { email, password } = req.body;
    
    // Mock authentication (in production, check against database)
    if (email === 'user@example.com' && password === 'password') {
      res.json({
        success: true,
        user: { id: 1, email, name: 'John Doe' },
        token: 'mock-jwt-token'
      });
    } else {
      res.status(401).json({ error: 'Invalid credentials' });
    }
  } catch (error) {
    res.status(500).json({ error: 'Login failed' });
  }
});

================================================================================
                              5. ERROR HANDLING
================================================================================

5.1 TRY-CATCH BLOCKS:
Every route handler is wrapped in try-catch blocks to handle errors gracefully.

5.2 ERROR MIDDLEWARE:
app.use((err, req, res, next) => {
  console.error(err.stack);
  res.status(500).json({ error: 'Something went wrong!' });
});

5.3 404 HANDLER:
app.use('*', (req, res) => {
  res.status(404).json({ error: 'Route not found' });
});

EXPLANATION:
- Try-catch: Catches JavaScript errors in route handlers
- Error middleware: Catches any unhandled errors
- 404 handler: Returns error for non-existent routes
- HTTP status codes: 200 (OK), 201 (Created), 400 (Bad Request), 401 (Unauthorized), 404 (Not Found), 500 (Server Error)

- Change PORT in .env file
- Kill process using the port
- Use different port for development

10.3 MODULE NOT FOUND:
- Run npm install
- Check if all dependencies are installed
- Verify file paths

10.4 API NOT RESPONDING:
- Check if server is running
- Verify endpoint URLs
- Check console for errors
- Test with curl or Postman
